# نموذج مركز إدارة المحتوى

## الهدف

يعطي مركز إدارة المحتوى فريق المؤسسة قدرة عملية على تعديل النصوص والأقسام وروابط التنقل من لوحة واحدة، من دون الحاجة إلى تعديل الكود. لا يحوّل المركز المنصة إلى محرر مفتوح قد يكسر المسارات أو ينشر ادعاءات غير معتمدة؛ فالعناصر الحساسة والقنوات الرسمية تُعامل كبيانات محمية أو تحتاج إلى مراجعة واعتماد.

## مستويات التعديل

| المستوى | أمثلة | أسلوب الإدارة | الحماية |
|---|---|---|---|
| **واجهة الصفحة الرئيسية** | عنوان البطل، الوصف، عناوين الأقسام، نصوص الأزرار، إظهار القسم وترتيبه | تبويب «الواجهة والأقسام» | لا يقبل عنواناً أو زرّاً فارغاً عند تفعيل القسم. |
| **محتوى الصفحات** | عن المؤسسة، الشفافية، الشراكات، منهجية الأثر | تبويب «المحتوى المؤسسي» | لا ينشر وثائق أو أرقاماً؛ هذه تدار من تبويباتها الخاصة. |
| **التنقل والتذييل** | تسمية الرابط، الترتيب، الظهور، وصف التذييل | تبويب «التنقل والتذييل» | روابط الإدارة والخصوصية والتواصل الأساسية لا تحذف ولا تتحول إلى رابط خارجي. |
| **المحتوى التشغيلي** | المشاريع، الإنجازات، الوسائط، الوثائق، المهام، الأولويات | تبويبات مستقلة قائمة بالفعل | تظل حالة النشر والموافقة وحقوق الاستخدام إلزامية. |
| **القنوات الرسمية** | الهاتف وWhatsApp وInstaPay والبنك | حقول محمية مع إرشادات تغيير واضحة | لا تعدل حتى تعتمدها المؤسسة وتختبر الرابط؛ لا يعتبر فتح الرابط تأكيد تبرع. |

## نموذج البيانات المقترح

تستمر المنصة في استخدام وثيقة `settings` الافتراضية في Firestore، مع حقول اختيارية لتفادي كسر أي محتوى قائم. يضاف كائنان منظمـان:

```ts
homepageSections: {
  hero: { enabled, eyebrow, title, description, primaryCtaLabel, secondaryCtaLabel },
  impact: { enabled, heading, description },
  programs: { enabled, eyebrow, heading, description, ctaLabel },
  partnerships: { enabled, eyebrow, heading, description, ctaLabel },
  media: { enabled, eyebrow, heading, description, ctaLabel },
  donate: { enabled, eyebrow, heading, description },
  sectionOrder: ["impact", "priorities", "programs", "partnerships", "donate"]
}

navigation: {
  items: [{ id, label, href, enabled, order }],
  donateLabel: "تبرع الآن",
  brandShortName: "مؤسسة مشروعنا",
  footerDescription: "..."
}
```

> **قاعدة النشر:** يمكن إخفاء القسم أو تغيير ترتيبه أو نصوصه، لكن لا تُنشأ حالة إنسانية أو رقم أثر أو قناة دفع أو وثيقة من هذه الواجهة. تُدار الأولويات والوثائق والقنوات التشغيلية من تبويبات متخصصة وبمصادر اعتماد واضحة.

## تجربة الإدارة المبسطة

سيبدأ المسؤول من تبويب «واجهة الموقع» الذي يعرض بطاقات الأقسام بدل قائمة حقول طويلة. كل بطاقة تحتوي على مفتاح إظهار، عنوان، وصف مختصر، نص الزر، وموضع ترتيب. يلي ذلك قسم «التنقل والتذييل» الذي يعرض قائمة الروابط بسحب منطقي/أسهم ترتيب وخيارات إظهار. ويحتوي كل تبويب على زر حفظ واحد ورسالة نجاح أو خطأ، مع رابط «افتح المعاينة العامة» لتدقيق النتيجة قبل النشر.

## الحواجز المطلوبة قبل الاعتماد الحي

لن تعتمد التجربة إلا بعد تطبيق قواعد Firebase التي تقصر كتابة `settings` على حسابات الإدارة، ثم اختبار تعديل كل حقل بحساب إداري وزيارة الموقع في نافذة غير مسجلة. ويظل حقلا الهوية والقنوات الرسمية غير قابلين للتعديل العام إلا بعد أن تؤكد المؤسسة البيانات الفعلية.
