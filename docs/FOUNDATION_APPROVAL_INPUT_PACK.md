# حزمة اعتماد المحتوى المؤسسي قبل النشر

**الغرض من هذه الحزمة** هو تحويل المعلومات التي لدى فريق المؤسسة إلى بيانات ومواد قابلة للنشر والمراجعة، من دون افتراض أرقام أو وثائق أو موافقات غير متاحة. تستخدم الحزمة معاً: فريق البرامج، المسؤول المالي أو الإداري، ومسؤول التواصل أو الإعلام. لا تُنشر أي خانة لم يراجعها صاحب الاختصاص داخل المؤسسة.

> هذه الحزمة قالب تشغيلي للموقع وليست رأياً قانونياً أو بديلاً عن وثائق التسجيل أو سياسات المؤسسة المعتمدة.

## 1. قواعد عامة للاعتماد

| القاعدة | التطبيق العملي |
|---|---|
| مصدر واحد معروف | يرفق كل رقم أو تصريح بمصدر داخلي واضح، مثل سجل برنامج أو قرار إداري أو تقرير موقع. |
| فترة زمنية محددة | لا يذكر عدد بلا شهر أو ربع أو سنة أو نطاق زمني واضح. |
| حالة نشر واضحة | تختار المؤسسة: **مسودة داخلية** أو **منشور للعامة** أو **مؤرشف**. |
| حماية المستفيدين أولاً | لا يُطلب أو ينشر اسم مستفيد أو رقم هويته أو عنوانه التفصيلي أو حالته الطبية أو التعليمية الحساسة. |
| مراجعة ثانية | يراجع شخص ثانٍ الرقم أو النص أو الوسيط قبل اعتماده للعامة. |

## 2. بطاقة البرنامج أو المشروع

تملأ بطاقة منفصلة لكل برنامج أو مشروع قبل إضافته من لوحة الإدارة.

| الحقل | ما يقدمه الفريق | مثال لصياغة آمنة |
|---|---|---|
| الاسم الرسمي للبرنامج | الاسم المعتمد داخل المؤسسة | برنامج دعم التعليم |
| وصف قصير | ما الذي يقدمه البرنامج دون وعد غير موثق | دعم احتياجات تعليمية وفق خطة تعتمدها المؤسسة. |
| المشكلة أو الاحتياج | وصف عام لا يكشف هوية الأفراد | احتياجات أسر وفئات مستهدفة في نطاق عمل المؤسسة. |
| النطاق الجغرافي | منطقة عامة فقط إن كان نشرها آمناً | القاهرة أو نطاق يحدده الفريق. |
| مرحلة البرنامج | مقترح، جارٍ، موسمي، مكتمل، مؤرشف | جارٍ بعد اعتماد الفريق. |
| النشاط الحالي | ما تم اعتماده فعلياً لا ما يؤمل تنفيذه | تواصل وتقييم احتياج، أو تنفيذ دفعة معتمدة. |
| مسؤول المراجعة | اسم داخلي أو دور وظيفي | مسؤول البرامج. |
| الملاحظات غير العامة | معلومات داخلية لا تظهر بالموقع | لا تنسخ إلى الوصف المنشور. |

## 3. نموذج اعتماد مؤشر الأثر

لا تُدخل الأرقام في عدادات الموقع أو بطاقات الأثر إلا بعد إكمال الجدول الآتي لكل مؤشر.

| الحقل | المطلوب |
|---|---|
| اسم المؤشر | وصف محدد، مثل «عدد حزم [نوع الخدمة] المسلّمة» وليس «عدد المستفيدين» فقط. |
| البرنامج المرتبط | اسم برنامج موجود أو معتمد للإضافة. |
| تعريف الاحتساب | ما الذي يعده الفريق وحدة واحدة؟ وما الذي لا يدخل في العدد؟ |
| القيمة | الرقم كما في المصدر، من دون تقريب دعائي. |
| الفترة | تاريخ بداية ونهاية أو تاريخ آخر تحديث. |
| المصدر | اسم السجل أو التقرير أو الملف الداخلي المسؤول. |
| جهة المراجعة | الشخص أو الدور الذي راجع صحة الرقم. |
| مستوى الثقة | منشور بعد مراجعة، أو قيد التوثيق، أو داخلي فقط. |
| ملاحظة أو حد للبيان | أي تغير في المنهج أو نقص في البيانات أو احتمال تكرار. |

> إذا لم يكتمل المصدر أو الفترة أو المراجعة، يظل المؤشر **قيد التوثيق** ولا ينشر كرقم أثر.

## 4. تحديث ميداني أو خبر مشروع

هذا النموذج مخصص للتحديثات التي يمكن أن تظهر في صفحة مشروع أو تقرير موجز، ولا يستخدم كقصة فردية عن مستفيد.

| الحقل | المطلوب قبل النشر |
|---|---|
| عنوان التحديث | عنوان وصفي غير مبالغ فيه. |
| التاريخ | تاريخ الحدث أو فترة التنفيذ. |
| ماذا حدث؟ | خطوات فعلية ومحددة، من دون ادعاء أثر لم يقس بعد. |
| الدليل الداخلي | رابط أو اسم سجل أو تقرير يتاح للفريق المراجع. |
| مكان عام | لا يذكر عنوان منزل أو موقعاً حساساً أو تفصيلاً يعرض المستفيدين للخطر. |
| مادة مرئية مرتبطة | رقم أو رابط مادة في المكتبة، بعد اعتماد الحقوق والموافقة. |
| حالة النشر | مسودة أو منشور أو مؤرشف. |

## 5. فهرس الوثائق والشفافية

يستكمل هذا الفهرس قبل وضع أي رابط في مركز الشفافية. تنشر المؤسسة النسخة المنقحة التي توافق عليها فقط، ولا تنشر نسخاً تحمل بيانات حساسة أو توقيعات أو أرقاماً غير مهيأة للنشر.

| الفئة | اسم الوثيقة | النسخة/السنة | موافقة النشر | رابط الملف المعتمد | ملاحظة تنقيح |
|---|---|---|---|---|---|
| التسجيل أو الترخيص |  |  | نعم / لا |  |  |
| الحوكمة |  |  | نعم / لا |  |  |
| سياسة حماية المستفيدين |  |  | نعم / لا |  |  |
| سياسة الخصوصية والبيانات |  |  | نعم / لا |  |  |
| تقرير أو ملخص مالي |  |  | نعم / لا |  |  |
| تقرير سنوي أو برنامج |  |  | نعم / لا |  |  |
| وثيقة أخرى |  |  | نعم / لا |  |  |

## 6. اعتماد وسائط الصور والفيديو

| الحقل | المطلوب |
|---|---|
| عنوان ووصف | يوضحان سياق المادة من دون كشف معلومات حساسة. |
| المشروع والتاريخ | اسم البرنامج وتاريخ التقاط تقريبي عند ملاءمة النشر. |
| نوع المادة | صورة أو فيديو، مع رابط التخزين الدائم بعد الرفع. |
| مصدر المادة | اسم المصور أو الجهة أو مصدر الترخيص. |
| حق النشر | بيان مختصر يثبت أن للمؤسسة حق النشر وفق موافقة أو ترخيص مناسب. |
| خصوصية المستفيدين | تأكيد أن النشر لا يضر بالكرامة أو يكشف بيانات أو موقعاً حساساً. |
| حالة النشر | مسودة أو منشور أو مؤرشف. |

## 7. ما تحتاجه حزمة العناية الواجبة للشراكات

يجمع الفريق هذه المواد في قناة آمنة متفق عليها مع الجهة الشريكة. لا يعني وجود بند في القائمة أنه منشور للعامة، ولا ينبغي رفع ملف إلى الموقع قبل مراجعة مناسبة.

| المجال | المادة المطلوبة من المؤسسة | مسؤول الاعتماد |
|---|---|---|
| الهوية القانونية | النسخ المعتمدة من التسجيل أو التفويض أو ما يلزم للجهة الشريكة | الإدارة أو المستشار المختص |
| الحوكمة | تعريف الأدوار، مجلس الأمناء أو الإدارة، وسياسات تضارب المصالح إن وجدت | الإدارة |
| البرامج | وصف برامج ونطاق وفئة مستهدفة ومنهج متابعة | فريق البرامج |
| المالية | ملخص أو تقارير أو ميزانية حسب متطلبات الجهة والشكل الذي توافق عليه المؤسسة | المسؤول المالي |
| الحماية | سياسة حماية المستفيدين والمدونة الإعلامية وسياسة التطوع | مسؤول الحماية أو الإدارة |
| البيانات | منهجية الأثر ومدة الاحتفاظ وإجراءات الوصول للبيانات | الإدارة والتقنية |
| العلامة والإعلام | الاسم المعتمد والشعار والبيان الإعلامي وشروط الاستخدام | مسؤول التواصل |

## 8. جلسة العمل عند توفر الـ laptop

بعد فتح لوحة الإدارة، ينفذ الفريق جلسة قصيرة وفق الترتيب التالي:

1. تحديد بريد/بريدين إداريين رسميين لتطبيق قواعد Firestore وتقييد رفع الوسائط.
2. إدخال برنامج واحد مع بطاقة البرنامج المكتملة، ثم نشره بعد مراجعة ثانية.
3. إدخال مؤشر واحد فقط بعد إرفاق المصدر والفترة والمراجع، أو إبقاؤه قيد التوثيق.
4. رفع مادة إعلامية واحدة بحقوق نشر واضحة واختبار ظهورها للعامة بعد النشر.
5. إضافة وثيقة واحدة منقحة ومعتمدة لمركز الشفافية، أو تأجيلها إن لم توافق المؤسسة على النشر.
6. إرسال طلب تجريبي للشراكة وطلب تطوع ورسالة تواصل، ثم التأكد من ظهورهما للمسؤول فقط.
7. حفظ نتيجة الاختبار في سجل مؤرخ، قبل أي إعلان أو حملة أو ربط نطاق نهائي.

## 9. ما يرسل للمطور قبل النشر النهائي

ينبغي أن يحسم الفريق هذه العناصر كتابةً قبل اعتبار الموقع جاهزاً للإطلاق:

- بريد الإدارة أو آلية custom claims المقترحة لرفع الوسائط وإدارة Firestore.
- القنوات الرسمية التي يسمح إظهارها للتبرع والتواصل، وأي قناة يجب إزالتها أو تعديلها.
- صياغة التعريف الرسمي للمؤسسة بالعربية والإنجليزية، ونسخة الشعار المسموح بها.
- قائمة البرامج الحقيقية وحالتها ومؤشرات كل برنامج التي اجتازت المراجعة.
- نسخ منقحة ومعتمدة من الوثائق التي تقرر المؤسسة نشرها أو مشاركتها عند الطلب.
- قرار مكتوب بشأن مدة الاحتفاظ بطلبات التواصل والشراكة والتطوع قبل تشغيل CRM أو نشرة بريدية.
- أي مزود دفع رسمي، سياسة الإيصالات، وآلية قياس التبرع التي توافق عليها المؤسسة.
